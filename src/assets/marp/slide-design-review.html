01 — Design Critique

What the current slides get wrong

The existing Keynote deck uses a default white theme with no brand identity. Here's a systematic breakdown of every issue — and what the redesign fixes.

✗ Issue
No brand identity
The only brand element is "PMP MASTERY FRAMEWORK" as plain text on one slide. No logo mark, no brand colors (#5b27b8, #3d1a7a, #c7951e), no Poppins font. Indistinguishable from a default Keynote deck.
✗ Issue
Incoherent image strategy
Three visual sources mixed with no rationale: stock beach/dune photos (zero PM relevance), a Gemini-generated "PASS" archery target with clip-art overlays, and a staircase infographic. Each has different art direction, colour temperature, and quality level.
✗ Issue
White everywhere = no hierarchy
Cover slide, section dividers, and content slides are visually identical — all white. There's no visual signal for "you're on a new section" or "this is a key callout." Every slide reads at the same weight.
✗ Issue
Generic AI-generated visuals
The Gemini infographics use orange, teal, and multicolour gradients — the base-tier PMP Exam Prep brand palette. They actively undermine Mastery Framework's premium positioning and inject a completely different visual identity.
✗ Issue
Default Keynote fonts
Arial/Helvetica rendered at inconsistent sizes. No Poppins (the brand font), no uppercase tracking on headings, no weight hierarchy between 900-weight display titles and 300-weight subtitles as specified in the brand manual.
✗ Issue
Not Marp-native despite YAML header
The source file uses a generic default theme. No slide class directives (cover, section, dark, stat), no custom CSS applied, no footer/logo. The Marp setup is present but completely unarmed — it outputs an unstyled deck.
✓ Strong
Solid content structure
The actual learning content is well-organised: clear modules, relevant topics (ECO domains, project vs. ops, delivery approaches). Day 1 scope is appropriate. This content just needs the right visual container.
✓ Strong
Marp toolchain already in place
The YAML frontmatter and existing slides.md architecture are correct. Upgrading from default to the custom pmp-mastery theme is a single configuration change — no content rewriting needed.

What the redesign fixes

Typography
Poppins 900 → 300 weight hierarchy
Cover/section titles at 900 weight, eyebrow labels at 700 with 0.28em tracking, body at 400 — exactly matching the brand manual type system.
Color
Deep purple + gold accent system
Cover/section slides on #3d1a7a. Content slides on white with 6px brand-gradient left bar. Gold accent on rules, eyebrows, list markers. Monochrome for print.
Slide Classes
6 purpose-built layouts
cover · section · content · dark · stat · quote · tips · agenda — each with precise spacing, colour, and typographic rules purpose-built for their role.
Images
CSS-native visual hierarchy, no images needed
Brand-colored backgrounds, domain percentage cards, week-plan grids, and styled tables replace the mismatched stock/AI images. Works at every screen size, exports cleanly to PDF.

04 — Export Pipeline

Automated Batch Export

One command exports every slides.md in your course tree to PDF and PPTX, applying the brand theme automatically. Zero manual effort per deck.

📝
slides.md
Marp Markdown with class directives
→
🎨
pmp-mastery.css
Brand theme applied automatically
→
⚙️
Marp CLI
@marp-team/marp-cli renders decks
→
📦
dist/slides/
PDF + PPTX per week/day

1. Install Marp CLI

npm install --save-dev @marp-team/marp-cli

2. Project structure

src/ themes/ pmp-mastery.css # brand theme → copy from deliverable generated/ week-1/ day-1/ slides.md # theme: pmp-mastery in frontmatter day-2/ slides.md week-2/ day-1/ slides.md scripts/ export-slides.mjs # batch export script → copy from deliverable dist/ slides/ # auto-created, gitignored week-1/ day-1/ slides.pdf slides.pptx package.json

3. package.json scripts

{ "scripts": { "slides": "node scripts/export-slides.mjs", "slides:pdf": "node scripts/export-slides.mjs --pdf", "slides:pptx": "node scripts/export-slides.mjs --pptx", "slides:html": "node scripts/export-slides.mjs --html", "slides:watch": "node scripts/export-slides.mjs --watch", "slides:day1": "node scripts/export-slides.mjs --week 1 --day 1" } }

4. Usage

# Export all decks (PDF + PPTX) npm run slides # Quick HTML preview (fast, no headless Chrome needed) npm run slides:html # Just Day 1 of Week 1 npm run slides:day1 # Watch mode — re-exports on file save npm run slides:watch # VS Code live preview while editing # Install "Marp for VS Code" extension → Cmd+Shift+P → "Marp: Open Preview"

5. Fix absolute image paths (existing slides)

# Your current slides.md uses file:/// absolute paths — these break on other machines. # Run this one-liner to convert all absolute paths to relative: find src/generated -name "slides.md" -exec \ sed -i 's|file:///[^ ]*/\([^/)]*\)|\1|g' {} \; # Then move images to src/generated/week-N/day-N/images/ # and reference them as: ![bg left:40%](images/photo.jpg)
