# Skill: Manage and Control Changes (pmp_change_management)

## Domain: Business Environment

## Focus Areas
Change Control Process, CCB, Impact Analysis, Agile Flex, Documentation Updates

## Description
This micro-skill enables the agent to perform the PMP ECO Task: "Manage and control changes" (Domain III, Task 3). The PM executes the change control process, communicates change status, implements approved changes, and keeps project documentation current.

## ECO Enablers
- Execute the change control process.
- Communicate the status of proposed changes.
- Implement approved changes to the project.
- Update project documentation to reflect changes.

## PMP Context
- **ECO Alignment**: Domain III Business Environment — Task 3 (2026 ECO). Note: moved from Process to Business Environment in 2026 update.
- **Exam Weight**: Part of Business Environment domain (26% of exam).
- **Approach Mix**: Predictive: formal CCB (Change Control Board), change request forms, impact analysis, approval workflow. Agile: backlog refinement as the change mechanism — changes enter the backlog and are prioritized, not submitted as formal change requests. Hybrid: formal CCB for scope/budget changes; agile backlog for feature-level changes within approved scope.
- **AI/Sustainability Lens**: AI can assist change impact analysis; sustainability-related regulatory changes may mandate project scope changes that bypass normal CCB discretion.
- **Knowledge Base**: Leveraging PMP Mastery content and BABOK v3 atoms.

## Key Concepts
- Integrated change control: no change is implemented without evaluating impact on all project constraints (scope, schedule, cost, quality, risk, resources).
- CCB authority levels: some changes require sponsor approval, others are within PM authority — exam questions frequently test who has the authority to approve.
- In agile: the product owner controls scope changes via backlog prioritization; there is no formal CCB.
- Documenting approved changes: project management plan, project documents, and the change log must all be updated — neglecting documentation is a common exam trap.

## Usage
- Trigger whenever a proposed change to scope, schedule, cost, or quality is identified.
- Cross-reference with `pmp_scope_management`, `pmp_integration_planning`, `pmp_governance_establishment`, `pmp_risk_management`.
